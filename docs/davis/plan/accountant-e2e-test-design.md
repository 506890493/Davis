## 1. 背景

会计（account）是 Davis 系统的核心执行角色，负责催收、续费、终止三大业务流程中的任务执行环节。已存在 `AccountantRolePermissionTest.java`（17 个用例），覆盖了基本的权限验证和核心流程。本文档识别缺口并设计补充测试用例。

## 3. 缺口分析

| 类别 | 缺口 | 优先级 |
|------|------|--------|
| **状态流转边界** | 非法状态转换（直接从待处理确认收款、已完成状态再次操作等） | P0 |
| **参数校验** | 确认收款时 actualAmount 为 0/负数/超大值 | P0 |
| **多轮协商** | 退回讲价 → 经理拒绝 → 再次退回 → 经理同意 → 收款 | P1 |
| **续签不生成新合同** | `completeRenewal` 时 `generateContract=false` | P1 |
| **通知验证** | 关键操作后的站内信通知（任务派发、退回讲价、审批完成） | P1 |
| **合同查询权限** | 会计能否查看关联合同的详情？能否查看合同列表？ | P1 |
| **个人资料管理** | 会计修改密码、头像、基本信息 | P2 |
| **任务列表筛选** | 按 taskType/status 筛选任务列表 | P2 |
| **首页仪表板** | 会计登录后首页显示个人待办统计数据 | P2 |
| **站内信已读** | 会计查看通知后标记已读 | P2 |

### 4.3 多轮协商测试（P1）

---

**用例 AT-24：两轮退回讲价最终成功流程**

| 步骤 | 角色 | 操作 | 验证点 |
|------|------|------|--------|
| 1 | manager | 创建任务，分配给 zhangsan | status="0" |
| 2 | zhangsan | 退回讲价，currentAmount=9000 | status="2" |
| 3 | manager | 拒绝协商（`rejectPrice`） | status="0"，金额不变 |
| 4 | zhangsan | 再次退回，currentAmount=9500 | status="2" |
| 5 | manager | 重新派发（`redispatch`） | status="0"，金额=9500 |
| 6 | zhangsan | 确认收款，actualAmount=9500 | status="4" |
| 7 | - | 验证任务日志 | 日志包含：创建→退回→拒绝→再退回→派发→收款 |

## 6. 实现优先级

**第一阶段（P0）**：状态边界 + 参数校验 — 防止数据异常
**第二阶段（P1）**：多轮协商 + 通知 + 权限边界 — 补全核心流程
**第三阶段（P2）**：个人资料 + 筛选 + 仪表板 — 辅助功能完善

## 7. 不覆盖的范围

- 并发操作（多会计同时操作同一任务）— 后续专项测试
- 定时任务自动生成续费任务 — 单元测试覆盖
- 令牌过期/刷新场景 — 后续安全测试
- 数据库事务回滚 — 单元测试覆盖
