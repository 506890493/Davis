# 催缴任务管理模块优化设计

## 1. 背景与目标

优化现有催缴任务管理流程，完善任务分配、协商价格审批、合同生成和审计日志功能。

## 2. 业务流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              催缴任务完整流程                                   │
└─────────────────────────────────────────────────────────────────────────────┘

1. 任务创建                    2. 任务执行                    3a. 续费结果
   ┌──────────────               ┌──────────────               ┌──────────────
   │ 经理发现需催   ──────>     │ 会计开始处理 ──────>       │ 客户同意续费
   │ 缴的合同                    │ (状态→进行中)                │
   │                            │                            │
   │ 创建催缴任务               │ 联系客户                    │ 3b. 终止结果
   │ - 基于原合同               │ 续费/不续费                 │    ┌──────────
   │ - 默认原会计               │                            │    │ 客户不续费
   │ - 可选其他会计(下拉框)      │                            │    │    │
   └──────────────               └──────────────               └────┼──────
                                                                     
   ┌─────────────────────────────────────────────────────────────────────┐
   │                        协商价格流程 (仅续费时)                         │
   └─────────────────────────────────────────────────────────────────────┘
   
   会计输入新价格 ──> 提交经理审批(状态→待审批) ──> 经理在"待审批任务"页面审批
                                                                    │
                                       ┌────────────┬─────────────┘
                                       │同意         │拒绝
                                       ▼            ▼
                                 金额更新为新价格    任务退回给会计
                                 (显示原→新)        (可重新协商)
                                       │            
                                       ▼            
                                 会计收费 ──> 完成催缴
                                                    │
                                                    ▼
                                            弹窗:是否生成新合同?
                                            - 是:填写新价格+期限→生成待审批合同
                                            - 否:任务结束
```

## 3. 功能清单

| 序号 | 功能点 | 现状 | 改进内容 | 优先级 |
|------|--------|------|----------|--------|
| 1 | 创建催缴任务-会计选择 | 手动输入会计ID | 下拉框选择，默认带出原合同会计 | P0 |
| 2 | 待审批任务页面 | 需在任务列表筛选status=2 | 新增独立的待审批任务页面 | P0 |
| 3 | 协商价格审批 | 无专门页面 | 待审批页面可批准/拒绝，显示原金额→新金额 | P0 |
| 4 | 终止合作审批 | 无专门页面 | 待审批页面可批准/拒绝 | P0 |
| 5 | 生成新合同 | completeRenewal不生成合同 | 弹窗让会计选择，填写新价格+期限后生成待审批合同 | P0 |
| 6 | 审计日志 | 部分记录 | 完善协商价格全过程记录 | P1 |

## 4. 详细设计

### 4.1 创建催缴任务 - 会计下拉选择

**前端页面改动** (`ruoyi-ui/src/views/system/task/index.vue`)

- 新增"创建催缴任务"对话框
- 增加"关联合同"选择器（可选，需先选择合同才能选会计）
- 增加"执行会计"下拉框
  - 打开下拉框时调用 `/system/task/assignableUsers` 获取会计列表
  - 默认选项：关联合同的归属会计（ownerId）
  - 支持搜索过滤

**后端接口**

- 现有接口 `/system/task/assignableUsers` 已存在，返回会计用户列表

### 4.2 待审批任务页面

**新增前端页面** (`ruoyi-ui/src/views/system/task/pending.vue`)

- 路由: `/system/task/pending`
- 仅展示 status=2（待审批）的任务
- 支持按任务类型筛选：协商价格 / 终止合作

**审批操作**

- 协商价格审批：
  - 显示：原金额 → 新金额
  - 操作按钮：同意 / 拒绝
  - 拒绝时需填写原因
- 终止合作审批：
  - 显示：终止原因
  - 操作按钮：同意 / 拒绝
  - 拒绝时需填写原因

**后端接口调整**

- 现有接口可用：
  - `/system/task/returnToAdmin` - 会计退回讲价
  - `/system/task/redispatch` - 经理重新派发
  - `/system/task/requestTermination` - 会计发起终止
  - `/system/task/confirmTermination` - 经理确认终止

### 4.3 协商价格流程优化

**前端页面改动**

- 会计操作：任务详情页/任务行操作中新增"协商价格"按钮
  - 弹出对话框：输入新价格 + 备注
  - 提交后状态变为 2（待审批）
- 经理审批：在待审批页面
  - 显示原金额 → 新金额
  - 同意：更新任务 currentAmount，状态变回 0（待处理），记录日志
  - 拒绝：任务状态不变，记录日志，提示会计可重新协商

**审计日志记录**

| 操作 | actionType | remark 格式 |
|------|------------|-------------|
| 会计提交新价格 | PRICE_SUBMIT | `提交协商价格: 原金额{originalAmount}→新金额{currentAmount}, 备注: {remark}` |
| 经理同意 | PRICE_APPROVE | `同意协商价格: 新金额{currentAmount}, 备注: {remark}` |
| 经理拒绝 | PRICE_REJECT | `拒绝协商价格, 原因: {remark}` |

### 4.4 生成新合同

**前端页面改动**

- 修改任务完成逻辑：
  - 会计点击"完成催缴"时，弹出确认对话框
  - 对话框内容：
    - 任务信息摘要（客户名、合同号、金额）
    - 单选项：「生成新合同」/「不生成」
    - 若选择「生成新合同」：
      - 输入框：新合同价格（默认带出协商后的 currentAmount，可修改）
      - 输入框：新合同期限（起止日期，默认原合同结束日期+1年）
  - 点击确认后：
    - 若生成合同：调用创建合同接口（auditStatus=0 待审批），更新任务状态为已完成，关联新合同ID
    - 若不生成：仅更新任务状态为已完成

**后端接口改动**

- 修改 `completeRenewal` 方法：
  - 新增参数：newAmount, newStartDate, newEndDate, generateContract
  - 若 generateContract=true：
    1. 创建新合同（复制原合同信息，更新金额、日期、状态为待审批）
    2. 设置 task.targetContractId = 新合同ID
    3. 设置 task.status = 4（已完成）

### 4.5 审计日志完善

**CmsTaskLog 表字段扩展**

| 字段 | 类型 | 说明 |
|------|------|------|
| log_id | Long | 主键 |
| task_id | Long | 任务ID |
| operator_id | Long | 操作人ID |
| operator_name | String | 操作人名称 |
| action_type | String | 操作类型 |
| before_status | String | 变更前状态 |
| after_status | String | 变更后状态 |
| amount_before | BigDecimal | 变更前金额（新增） |
| amount_after | BigDecimal | 变更后金额（新增） |
| remark | String | 备注 |
| create_time | Date | 创建时间 |

**action_type 枚举**

| 值 | 说明 |
|----|------|
| CREATE | 创建任务 |
| START | 开始处理 |
| PRICE_SUBMIT | 提交协商价格 |
| PRICE_APPROVE | 同意协商价格 |
| PRICE_REJECT | 拒绝协商价格 |
| TERMINATE_SUBMIT | 提交终止合作 |
| TERMINATE_APPROVE | 同意终止合作 |
| TERMINATE_REJECT | 拒绝终止合作 |
| COMPLETE | 完成任务 |
| REDISPATCH | 重新派发 |
| PAYMENT | 确认收款 |

## 7. 确认事项

- [x] 不支持批量审批
- [x] 合同期限可修改（生成合同时手动输入）
- [x] 需要站内通知

## 8. 通知机制

| 触发场景 | 通知人 | 接收人 | 通知内容 |
|----------|--------|--------|----------|
| 会计提交协商价格 | 会计 | 经理 | "您有新的协商价格待审批：任务【{taskTitle}】，原金额→新金额" |
| 经理同意协商价格 | 经理 | 会计 | "您的协商价格已通过：新金额【{amount}】" |
| 经理拒绝协商价格 | 经理 | 会计 | "您的协商价格已拒绝，原因：{reason}" |
| 会计提交终止合作 | 会计 | 经理 | "您有终止合作待审批：任务【{taskTitle}】" |
| 经理同意终止合作 | 经理 | 会计 | "终止合作已确认" |
| 经理拒绝终止合作 | 经理 | 会计 | "终止合作已拒绝，原因：{reason}" |
| 任务完成生成新合同 | 会计 | 经理 | "已完成催缴任务【{taskTitle}】，已生成待审批合同" |

**通知实现**：复用现有 `SysNotice` 机制，参照 `insertCmsTask` 中的通知逻辑。
